# VantageOps

**Enterprise resource and analytics dashboard built as a Python application with a Python API.**

[![Python CI](https://github.com/dismality/vantageops/actions/workflows/ci.yml/badge.svg)](https://github.com/dismality/vantageops/actions/workflows/ci.yml)

VantageOps turns raw sales, product, supplier, and inventory records into decisions an operations leader can act on. The interface, business logic, data processing, forecasting, scenario calculations, upload validation, and API are all written in Python.

![VantageOps Python executive overview](docs/images/01-overview.png)

## Why this version is Python-first

The first prototype used a TypeScript/React interface with a Python analytics pipeline. This version removes that split. Dash creates the browser interface from Python, Plotly creates the charts from Python, and Flask exposes the same trusted metrics through JSON endpoints.

There are **no TypeScript, TSX, Node, npm, or React source files** in this repository.

## What each feature does

### 1. Executive overview

This page answers, “How is the business doing right now?” It combines revenue, margin, inventory efficiency, risk exposure, recent trends, and the most important recommended action.

![Executive overview with Python-generated KPIs and charts](docs/images/01-overview.png)

### 2. Forecast lab

This page answers, “What is likely to happen over the next 90 days?” Python calculates an explainable trend forecast, a reasonable high and low range, forecast accuracy, and regional target performance.

![Forecast lab generated by Python and Plotly](docs/images/02-forecast-lab.png)

### 3. Risk monitor

This page answers, “What needs attention first?” Python ranks operational risks using severity, estimated financial exposure, and confidence. Every alert includes a plain-English reason and suggested action.

![Python risk monitor with ranked financial exposure](docs/images/03-risk-monitor.png)

### 4. Scenario planner

This page answers, “What could happen if the plan changes?” Adjust demand, price, cost, and inventory assumptions. A Python callback immediately recalculates revenue, gross margin, working capital, service level, and profit impact.

![Python scenario planner with interactive assumptions](docs/images/04-scenario-planner.png)

### 5. Data pipeline

This page answers, “Can I trust these numbers—and what did we sell each month?” It shows ingestion, validation, quarantine, transformation, and publishing. A user can upload a transaction-level CSV with one row per purchase. Python checks each row, calculates revenue after discounts, and creates a stacked monthly bar chart by product, summary metrics, and a recent-purchases table. The file stays in memory and is not stored.

![Python data pipeline with an uploaded monthly sales report](docs/images/05-data-pipeline.png)

#### Sales upload format

Start with the included [example sales file](assets/sample_sales_upload.csv), or use these common column names:

| Information | Suggested column | Also accepted |
| --- | --- | --- |
| When the purchase happened | `sale_date` | `order_date`, `date`, `transaction_date`, `sold_at` |
| What was purchased | `product` | `product_name`, `item`, `item_name`, `product_id` |
| How many units were sold | `quantity` | `qty`, `units`, `units_sold` |
| Price for one unit | `unit_price` | `price`, `sale_price`, `price_each` |
| Optional discount | `discount_pct` | `discount`, `discount_percent` |

Discounts can be written as `10` or `0.10` for 10%. Rows with a bad date, missing product, zero/negative quantity, or invalid price are rejected and counted clearly instead of silently changing the report.

## Python API

The dashboard and API use the same in-memory analytics snapshot, which prevents two different versions of a KPI.

| Endpoint | Simple explanation |
| --- | --- |
| GET /api/health | Confirms the Python service is running |
| GET /api/kpis | Returns revenue, margin, turnover, and accepted rows |
| GET /api/forecast | Returns the 90-day forecast and confidence range |
| GET /api/risks | Returns ranked operational risk alerts |
| GET /api/pipeline | Returns row counts and data-quality checks |

Example response:

~~~json
{
  "gross_margin_pct": 36.66,
  "inventory_turnover": 21.14,
  "net_revenue": 45590238.71
}
~~~

## Architecture

~~~mermaid
flowchart LR
  A[Sales and product CSVs] --> B[Pandas validation]
  B --> C[Quarantine bad rows]
  B --> D[Finance calculations]
  D --> E[SQLite and analytical marts]
  E --> F[NumPy forecast and risk rules]
  F --> G[Dash interface]
  F --> H[Flask JSON API]
~~~

## Technology

- **Python:** the entire application and analytics layer
- **Pandas and NumPy:** validation, transformations, KPIs, forecasting, and risk scoring
- **Dash and Plotly:** interactive interface and charts defined in Python
- **Flask:** read-only JSON API endpoints
- **SQLite and SQL:** portable analytical storage and reusable transformation logic
- **Pytest:** calculation, scenario, upload analysis, schema, and API tests
- **Gunicorn and Docker:** production server and reproducible deployment

## Run locally

~~~bash
python -m venv .venv
~~~

Activate the environment:

~~~bash
# Windows
.venv\Scripts\activate

# macOS or Linux
source .venv/bin/activate
~~~

Install and run:

~~~bash
pip install -r requirements.txt
python app.py
~~~

Open http://localhost:8050.

Run the standalone analytics pipeline:

~~~bash
python -m pipeline.main
~~~

Run the tests:

~~~bash
pytest -q
~~~

## Data quality demonstration

The deterministic pipeline generates 18,420 source rows. It accepts 18,274 trustworthy rows and quarantines 146 deliberate problems:

- 120 rows with missing product references
- 26 duplicate order IDs

Quarantined records are preserved for review instead of being silently deleted.

## Business value

| Business problem | VantageOps response | Measure for a real pilot |
| --- | --- | --- |
| Analysts rebuild reports manually | One repeatable Python pipeline publishes every metric | Reporting hours saved |
| Leaders find stock problems too late | Risk is ranked by financial exposure | Revenue protected |
| Forecasts feel like black boxes | Trend, range, and accuracy are visible | MAPE and forecast bias |
| Teams disagree about KPIs | Dashboard and API share one Python calculation path | Reconciliation issues |
| Decisions rely on intuition | Scenario assumptions show trade-offs immediately | Outcome variance |

An illustrative adoption target is reducing a 10-hour weekly reporting process by **60–80%**. This is a product hypothesis for a future pilot, not a measured claim from synthetic data.
